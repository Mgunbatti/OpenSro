# GM-003: the account JID query is formatted twice

- Original: `CServiceManagerProcess` 0x7411 handler (sub_44A380), GlobalManager
- Rewrite: `CServiceManagerProcess::OnMsg_7411` in `JMX_CommonServers/GlobalManager/ServiceManagerAccount.cpp`
- Severity: medium

## What the original does

The handler builds the query text for the account name from the SMC with `StringCchPrintfA` into
a 3 KB buffer (the table depends on the division: `sr_member1`, `_User` or `TB_User`) and then
passes that text as the format string to `CDBQuery::ExecuteFormat` without arguments. The account
name is not escaped either.

## Effect

An account name with `%` sequences is interpreted a second time by `_vsnprintf_s`: `%s` or `%n`
read (or write through) whatever is on the stack, which can crash the GlobalManager. A quote in
the name ends the SQL string literal (SQL injection). The request needs a logged-in SMC.

## Fix

Execute the formatted text as it is (`ExecuteFormat("%s", text)` or copy it into the query and
call `Execute`), and escape quotes in the account name.
