# GM-001: failed 0x6307 and 0x620D relays keep their relay context

- Original: `CServiceManagerProcess` 0x7202 handler (sub_4465C0), 0xA307 handler (sub_446700) and
  0x7201 handler (sub_446370), GlobalManager
- Rewrite: `CServiceManagerProcess::OnMsg_7202` / `OnMsg_A307` in
  `JMX_CommonServers/GlobalManager/ServiceManagerControl.cpp`, `OnMsg_7201` in
  `JMX_CommonServers/GlobalManager/ServiceManagerAccount.cpp`
- Severity: low

## What the original does

For every GatewayServer of the architecture the handler takes an `sSMDefault_RelayMsg_Param` from
its pool (the SMC session and the gateway's body ID) and relays 0x6307 to the gateway with it as
context. When the relay fails (no route or the send fails) it answers 0xB202 {gateway, 2} to the
SMC but never releases the context. Every other service manager handler releases the context in
that case, and the answer handler of 0x6307 (0xA307) does not release it either. The ban request
0x7201 does the same when the 0x620D relay to the user's AgentServer fails: it answers 0xB201
{2, 2} and keeps the context.

## Effect

Each 0x7202 request leaks one pool object per unreachable GatewayServer (and one per reachable
one, since 0xA307 keeps it as well); each failed ban leaks one. The pool grows by blocks of 500
objects; the memory is only returned at exit.

## Fix

Release the context after the failure answers of `OnMsg_7202` and `OnMsg_7201` and at the end of
`OnMsg_A307`.
