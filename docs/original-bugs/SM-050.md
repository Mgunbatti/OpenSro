# SM-050: A teleport link with an unknown owner teleport crashes the start-up

- Original: `CRefInstanceGenerator::LoadTeleLink` (0x4a41f0), SR_ShardManager
- Rewrite: `RefData_LoadTeleLink` in `SilkroadOnline/Server/ServerCommon/RefDataTeleport.cpp`
- Severity: major

## What the original does

For every `_RefTeleLink` row in service the loader looks up the owner teleport (OwnerTeleport)
in the teleport map. When there is no such teleport it only calls the release assert, which
returns, and then calls `RefTeleport::AddLink` (0x493c00) on the NULL teleport, which pushes the
link into a vector at address 0x38.

## Effect

One `_RefTeleLink` row whose OwnerTeleport is not an in-service `_RefTeleport` row makes
SR_ShardManager crash with an access violation while it builds the reference data, without a
message naming the row.

## Fix

Skip (and log) the link, free it, and go on with the next row, or fail the build with a message
naming the link.
