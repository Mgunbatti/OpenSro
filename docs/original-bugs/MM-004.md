# MM-004: stopping a module can hit another program with a similar name

- Original: `ServerProcess_CloseOrTerminate` (0x401620) with `Process_FindPidByExeName`
  (0x409950), MachineManager
- Rewrite: `MachineManager_CloseOrTerminateProcess` in
  `JMX_CommonServers/MachineManager/MachineManagerMainProcess.cpp`, `FindOtherProcessByExeName`
  in `JMX_ServerFramework/ServerFramework/ServerApp.cpp`
- Severity: medium

## What the original does

When the module has no window, its process is looked up in a process snapshot as the first
process (other than MachineManager) whose exe file name *starts with* the module name. The name
is compared case-sensitively and without the ".exe" boundary. The check whether the module runs
at all is the module's named semaphore, not the process found.

## Effect

Stopping "GameServer" can pick "GameServerTool.exe" or a second copy such as
"GameServer_old.exe" if it comes first in the snapshot, and that process is terminated after the
timeout. If the module itself runs only under a differently cased exe name, the wrong process (or
none) is found.

## Fix

Compare the whole exe name ("<module>.exe", case-insensitive) and prefer the process that owns
the module's semaphore or window.
