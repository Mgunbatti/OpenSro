# DB-001: Pool connections are freed without SQLDisconnect

- Original: `DBConnPool_FreeHandles` (0x476b00), GatewayServer
- Rewrite: `CDBSessionMgr::Close` in `JMX_Library/BSLib/DB/Database.cpp`
- Severity: major

## What the original does

`CDBSessionMgr::Close` runs over the 30 connection handles of a pool and calls
`SQLFreeHandle(SQL_HANDLE_DBC, h)` on each non-null one, then frees the array. There is no
`SQLDisconnect` anywhere in the library, so the handles are still connected when they are freed.
`CDatabase::DestroySession`, `CDatabase::DestroyAllSessions` (server shutdown) and the
destructor all end up here.

## Effect

The driver manager refuses to free a connected handle (SQLSTATE HY010, function sequence
error) and returns `SQL_ERROR`, which is ignored. The 30 connections of every pool stay open
until the process ends; on the database server the sessions remain until the client process is
gone. `DestroyAllSessions` then frees the environment handle while connections still use it,
which fails as well. A pool that is destroyed and recreated at run time leaks 30 connections
each time.

## Fix

Call `SQLDisconnect` on each handle before `SQLFreeHandle`, and free the environment only
after all connections are gone.
