# SM-060: A nest of an unknown hive crashes the reference data build

- Original: `CRefInstanceGenerator::LoadNest` (0x4a9e80), SR_ShardManager
- Rewrite: `RefData_LoadNest` in `SilkroadOnline/Server/ServerCommon/RefDataQuest.cpp`
- Severity: minor

## What the original does

After the TAB_REFNEST rows are read, every nest is appended to the nest vector of its hive,
looked up by HiveID in the hive map. When there is no hive with that ID (or its entry is NULL),
the loader asserts and then appends the nest through the NULL hive pointer anyway.

## Effect

A _RefNest row that names a hive missing from _RefHive (for example one out of service in the
database export) makes the ShardManager crash with an access violation during start-up instead
of reporting the table.

## Fix

Skip the nest (or fail the table with a message) when its hive is not found.
