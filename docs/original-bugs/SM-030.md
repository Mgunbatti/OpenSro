# SM-030: A rejected _RefDropItemGroup row is kept in group 0

- Original: `CRefInstanceGenerator::LoadDropItemGroup` (0x4a5a20) with `RefDropItemGroup::Read`
  (0x4925e0), SR_ShardManager
- Rewrite: `RefDrop_LoadDropItemGroup` in `SilkroadOnline/Server/ServerCommon/RefDataDrop.cpp`
- Severity: minor

## What the original does

The reader returns the group ID of the row, or 0 for a row out of service or with an unknown
magic option group. The loader does not look at the result: it only checks that the row's item
exists and then appends the row to the group of the returned ID, so every rejected row goes into
group 0.

## Effect

Rows switched off in `_RefDropItemGroup` are not dropped but collected under group ID 0. A drop
that refers to group 0 picks from them.

## Fix

Free the row when the reader returns 0.
