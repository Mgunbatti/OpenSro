# SM-270: Party matching requests trust the user's party ID

- Original: `CPartyManager::OnRegisterPartyMatch` (0x450680), `CPartyManager::OnPartyMatchList` (0x450d20), SR_ShardManager
- Rewrite: `CPartyManager::OnRegisterPartyMatch`, `CPartyManager::OnPartyMatchList` in `SilkroadOnline/Server/ShardManager/PartyManager.cpp`
- Severity: minor

## What the original does

When the requesting user has a party ID (CUser +0x68), both handlers call `FindParty` and read
the party's type (register) or master JID (list) without checking the result for NULL.
`RegisterMatchEntryForParty`, called right after, does check it.

## Effect

A user whose party ID points to a party that no longer exists crashes the shard manager with a
NULL read. Normally the party ID is cleared together with the party, so this needs an
inconsistent state.

## Fix

Answer 0x2C0D (no party) when `FindParty` returns NULL.
