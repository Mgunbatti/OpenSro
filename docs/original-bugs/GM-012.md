# GM-012: the security data lists leak when a query fails

- Original: `COverlapJob_RefreshSecurityData_n_SendToSM::vf06` (0x4258f0), GlobalManager
- Rewrite: `COverlapJob_RefreshSecurityData_n_SendToSM::Execute` in
  `JMX_CommonServers/GlobalManager/ServiceManagerJobs.cpp`
- Severity: low

## What the original does

The job allocates three new lists and reads `_SecurityDescription`, `_SecurityDescriptionGroup` and
`_SecurityDescriptionGroupAssign` into them (one record allocation per row). Only when all three
queries succeed are the lists handed to `CertData_BuildPrivilegedIPMaps`; when one fails, the lists
and the records read so far are never freed.

## Effect

Each failed refresh leaks the lists and records. The previous security data stays active.

## Fix

Free the lists and their records on failure.
