# GM-015: the punishment timer goes on from an erased map node

- Original: `sub_4596E0` (0x4596e0, CPunishmentManager, timer 0x22), GlobalManager
- Rewrite: `CPunishmentManager::Tick` in `JMX_CommonServers/GlobalManager/PunishmentManager.cpp`
- Severity: high

## What the original does

The timer walks the multimap of punishments. When an active punishment has ended it erases the
node, releases the punishment and then increments the iterator of the erased node (the iterator
returned by `erase` is stored and ignored).

## Effect

The increment reads the freed node (its right child and, without one, its parent). Depending on
what the heap wrote into the freed block the walk goes on correctly, skips or repeats entries,
or crashes the main process. The last entry in key order never has a right child, so ending it
always reads the parent pointer from freed memory.

## Fix

Continue with the iterator `erase` returns.
