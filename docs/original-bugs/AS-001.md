# AS-001: a refused complete massive message is freed twice

- Original: `CAgentMainProcess::Dispatch` (vf08, 0x401ac0) with `CServerProcessMain::OnMsg_600D` (0x42d480), AgentServer
- Rewrite: `CAgentMainProcess::Dispatch` in `JMX_CommonServers/AgentServer/AgentMainProcess.cpp`
- Severity: low

## What the original does

While the server is in service, `Dispatch` refuses messages of client sessions (no server cord)
whose opcode has none of the login exceptions and is not a plain client opcode (bit 0x1000 set,
0x8800 clear). For a refused massive message it looks the session up in the map of massive messages
being received, frees that `CMassiveMsg` and erases the entry, then closes the session. When the
refused massive message is the completed one that `OnMsg_600D` is dispatching, that is the same
object: after `Dispatch` returns, `OnMsg_600D` frees it again and erases the iterator it kept, which
points to the erased node.

## Effect

A double free of a pooled `CMassiveMsg` and an erase through a dangling map iterator. It needs a
massive message from a client whose parts passed the filter (for example because the server went
into service while it was being received) and whose inner opcode is refused on completion.

## Fix

Do not free the massive message in `Dispatch` (the caller owns it), or let `OnMsg_600D` look the
entry up again after `Dispatch`.
