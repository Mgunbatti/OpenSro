# FW11-028: CStringCheck reads past the end after a trailing lead byte

- Original: `String_ToLowerMbcs` (0x6df010) and `CStringCheck::AreCharsAllowed` (0x6df7f0), SR_ShardManager
- Rewrite: the same functions in `JMX_Library/BSLib/Util/StringCheck.cpp`
- Severity: low (needs a name ending in a lone double-byte lead byte)

## What the original does

Both functions treat a byte with the high bit set as the lead byte of a double-byte character and take the next byte as trail byte without checking it. When the lead byte is the last character, the terminator is taken as trail byte and the loop continues with the byte after the terminator.

## Effect

Reads beyond the string until some later zero byte; the lowered copy gets garbage appended and the character check looks at bytes that are not part of the name.

## Fix

Stop when the trail byte is zero.
