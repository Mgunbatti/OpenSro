# SM-271: A party matching entry that fails to write leaves bytes in the list page

- Original: `CPartyManager::RebuildMatchListCache` (0x451630), SR_ShardManager
- Rewrite: `CPartyManager::RebuildMatchListCache` in `SilkroadOnline/Server/ShardManager/PartyManager.cpp`
- Severity: minor

## What the original does

`PartyMatchEntry::WriteToMsg` (0x44f640) writes the entry ID and the registration time before it
can fail when the entry's party has lost its master. The rebuild then drops the entry but keeps
the bytes already written in the page message, and the page's entry count does not include
them.

## Effect

The list page sent to clients (0xB866 subtype 13) holds eight stray bytes in front of the next
entry, so every entry after it is parsed shifted.

## Fix

Remember the write position before `WriteToMsg` and restore it when the entry fails.
