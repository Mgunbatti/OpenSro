# FW11-024: RebuildEventList reports running periods with uninitialised times

- Original: `NewSchedule::CScheduleManager::RebuildEventList` (0x6bf740), SR_ShardManager
- Rewrite: `CScheduleManager::RebuildEventList` in `JMX_Library/BSLib/NewSchedule/ScheduleManager.cpp`
- Severity: low (only at service start, for a schedule that has no earlier period)

## What the original does

For every period running at service start the manager looks up the previous period of the group (`GetPrevPeriods(..., 1, now)`) and copies its begin and end into the event it hands to `OnServiceStartSchedule`. The local period it copies from is constructed but not cleared; when the group has no previous period (for example a rule that started today), the list stays empty and the event gets whatever was on the stack.

## Effect

The application (CShard_ScheduleManager) logs and dispatches the running schedule with random begin and end times.

## Fix

Clear the period, or keep the times of the running period when no previous one exists.
