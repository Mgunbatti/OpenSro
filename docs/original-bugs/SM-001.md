# SM-001: A full stream record buffer ends the process with an empty rethrow

- Original: `CDBRecStream::WriteRaw` (0x61a510), SR_ShardManager
- Rewrite: `CDBRecStream::WriteRaw` in `JMX_Library/BSLib/DB/Database.cpp`
- Severity: crash

## What the original does

`CDBRecStream::SetField` appends every fetched column to the record's buffer through
`WriteRaw`. When the bytes do not fit (write position + size > capacity) the function calls
`BSAssertFail` and then `_CxxThrowException(0, 0)`, the code of a bare `throw;`. No exception is
being handled at that point, so the C++ runtime calls `terminate`.

## Effect

The buffer is allocated with `CDBTableInfo::m_nRowSize` (the sum of the column buffer
lengths), so a string column longer than the bound size cannot overflow it; but any mismatch
between the row size and the written bytes (a changed table between `DescribeColumns` and the
fetch) does not fail the fetch, it takes the ShardManager down without a log line after the
assert.

## Fix

Throw a real exception that the fetch loop catches, or log and drop the column.
