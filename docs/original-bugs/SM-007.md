# SM-007: A reference row with a duplicate key leaks

- Original: the map inserts of the reference data loaders, e.g.
  `CRefInstanceGenerator::LoadTriggerCategory` (0x4a7b10), `LoadUIString` (0x4a7850),
  `RefData_BuildRefTriggerEvent` (0x4d0fc0), SR_ShardManager
- Rewrite: `RefData_BuildKeyed` in `SilkroadOnline/Server/ServerCommon/ReferenceData.cpp`
- Severity: minor

## What the original does

The loader allocates the parsed row, reads it and inserts (key, row) into a std::map of the
reference data without looking at the result of the insert. When the key (ID or code name) is
already in the map the insert does nothing and the new row is neither stored nor freed.

## Effect

Duplicate IDs or code names in a `_Ref` table are silently ignored (the first row wins) and each
duplicate leaks its row once per start-up.

## Fix

Free the row (and log the duplicate) when the insert reports an existing key.
