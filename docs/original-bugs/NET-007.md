# NET-007: a session whose socket cannot be attached stays registered

- Original: `Session_BindAndPostConnect` 0x4923b0 with `SessionTable_CreateNewSession` 0x4945e0
  (GatewayServer)
- Rewrite: `CSession::Bind` in `JMX_Library/BSNet/Session.cpp`,
  `CSessionTable::CreateNewSession` in `JMX_Library/BSNet/SessionTable.cpp`
- Severity: wrong

## What the original does

`CreateNewSession` takes a session and an ID, stores the session in its slot and calls
`Session_BindAndPostConnect`. That function links the session into the session list, posts the
connect event (0x1001) to the application and only then attaches the socket to the I/O proactor
(`AttachToProactor`, which associates the handle and posts the first receive). When the attach
fails it returns FALSE and `CreateNewSession` returns 0. Also when the task ID is unknown the
socket is already bound to the session before the failure.

## Effect

The caller sees a failed connect (`ConnectSockAddr` returns 0 and keeps the socket, the
listener disconnects it), but the application already got a connect event for an ID it will
never hear of again, the session stays linked and in its slot with the socket bound to it, and
the ID is used up until the maintainer reaps the session.

## Fix

Attach the socket before linking and posting, and on failure undo the binding (unlink, return
the session and the ID to their pools, release the socket).
