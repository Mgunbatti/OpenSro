# SM-274: Recruit list rebuild leaks a page message

- Original: `CRegMatchMgr_TrainingCampRegData::RebuildListMsgs` (0x45aca0), SR_ShardManager
- Rewrite: `CRegMatchMgr::RebuildListMsgs` in `SilkroadOnline/Server/ShardManager/TrainingCamp.cpp`
- Severity: minor

## What the original does

A page message is allocated whenever no entry has been written to the current page yet. When
the first entry of a fresh page is dropped (its registrant is offline) and more entries follow,
the next iteration allocates another message; the first one is neither stored nor released.
This is the same pattern as SM-272 in the party matching list.

## Effect

One message of the network engine's pool leaks per dropped entry at the start of a page.

## Fix

Allocate the page only when no page is open.
