# SM-040: A _RefObjCommon row with a duplicate ID leaks its object

- Original: `RefObjCommon_ReadAndCreate` (0x4a2cf0), SR_ShardManager
- Rewrite: `RefObjCommon_ReadAndCreate` in `SilkroadOnline/Server/ServerCommon/RefDataObj.cpp`
- Severity: minor

## What the original does

The row's object (RefObjChar, RefObjItem or RefObjStruct) is created and read, then (ID, object)
is inserted into the object hash_map without looking at the result of the insert. When the ID is
already there the insert does nothing and the object is neither stored nor freed.

## Effect

A duplicate object ID is silently ignored (the first row wins) and its object leaks once per
start-up.

## Fix

Free the object (and log the duplicate) when the insert reports an existing ID.
