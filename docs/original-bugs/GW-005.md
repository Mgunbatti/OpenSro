# GW-005: quote filter of the login strings tests the wrong byte

- Original: `String_ReplaceQuotesWithSpace` (0x4074b0), GatewayServer
- Rewrite: `String_ReplaceQuotesWithSpace` in `JMX_CommonServers/GatewayServer/GatewayMainProcess.cpp`
- Severity: high (SQL injection filter bypass)

## What the original does

The login request handler passes the user ID and password through this filter before they are
put into the certification query. It walks the string with `CharNextA` and replaces `'` and `"`
with a space, but only when `test word ptr [p], 0x8000` is zero, i.e. when the high bit of the
byte after the current one is clear. The intent was obviously to leave double-byte characters
alone; the check reads the wrong byte.

## Effect

A quote directly followed by a byte >= 0x80 is not replaced, so a login string can still carry a
quote into the SQL text of the certification query.

## Fix

Test the lead byte (`IsDBCSLeadByte(*p)`) or, better, pass the strings as query parameters.
