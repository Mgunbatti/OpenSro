# GW-003: failed _PrivilegedIP load frees the module version lists a second time

- Original: `CGatewayServer::InitDBAndModuleVersions` (0x403da0, vtable slot 11), GatewayServer
- Rewrite: `CGatewayServer::OnLocalDataInitialized` in `JMX_CommonServers/GatewayServer/GatewayServer.cpp`
- Severity: medium

## What the original does

The start-up loads _ModuleVersion and _ModuleVersionFile into two new lists and hands both to
`ModuleVersion_StoreAndIndexLists`, which keeps them as `g_pModuleVersionList` /
`g_pModuleVersionFileList`. The next step loads _PrivilegedIP. When that query fails it jumps to
the common error exit, which logs "cannot load module version data from DB" and deletes the two
lists through the local pointers.

## Effect

The module version globals then point to freed lists. The start-up returns false, but the next
user of the module version data (0x6100 version checks, `ModuleVersion_FreeAllData` at
shutdown) works on freed memory and frees the lists again.

## Fix

Clear the local pointers after `ModuleVersion_StoreAndIndexLists`, or use a separate error exit
for the steps after it.
