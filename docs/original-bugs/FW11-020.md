# FW11-020: the crash dump request block is leaked and not checked

- Original: `CrashDump_TopLevelExceptionFilter` (0x44f8c0) and `CrashDump_WriteDump` (0x44f2a0),
  AgentServer (2011 framework)
- Rewrite: `CrashDump_TopLevelExceptionFilter`, `CrashDump_WriteDump` in
  `JMX_ServerFramework/ServerFramework/CrashDump.cpp` (`JMX_FRAMEWORK_2011`)
- Severity: low

## What the original does

The 2011 top level exception filter allocates an 8-byte block {thread ID, exception pointers}
with `operator new` and passes it to the worker that writes the minidump (on a new thread after
a stack overflow). The block is never freed. When the allocation fails, the filter passes NULL
and the worker reads the thread ID and the exception pointers through it as soon as the dump
file is open.

## Effect

Every call of the filter leaks 8 bytes, which does not matter for a process that is about to
end. A failed allocation, which is likely after an out-of-memory crash, faults inside the
exception filter, so no dump is written.

## Fix

Use a block on the filter's stack (the filter waits for the worker thread) or check the
allocation and fall back to the current thread with the filter's own argument.
