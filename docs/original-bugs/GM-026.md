# GM-026: the security description lists leak when a start-up query fails

- Original: `sub_40C7B0` (0x40c7b0, called by `CGlobalManager::vf11`), GlobalManager
- Rewrite: `CGlobalManager::LoadSecurityDescriptions` in
  `JMX_CommonServers/GlobalManager/GlobalManager.cpp`
- Severity: low

## What the original does

`OnLocalDataInitialized` allocates three lists and reads `_SecurityDescription`,
`_SecurityDescriptionGroup` and `_SecurityDescriptionGroupAssign` of the division's database into
them (one record allocation per row, made by the row trigger). Only when all three queries succeed
are the lists handed to `CertData_BuildPrivilegedIPMaps`; when a query fails (or a query text does
not fit), the function returns false without freeing the lists and the records read so far.

## Effect

The memory is lost; the start-up fails anyway ("security description data loading failed....").

## Fix

Free the lists and their records before returning false.
