# GM-020: the ipv4 and ipv6 summary lines of a RIR file do not fit the record

- Original: `sub_462470` (0x462470, IP country table, RIR line parser), GlobalManager
- Rewrite: `CIPCountryTable::ParseRIRRecord` in
  `JMX_CommonServers/GlobalManager/IPCountryTable.cpp`
- Severity: high

## What the original does

The three summary lines of a delegation file (`apnic|*|asn|*|3838|summary`, then `ipv4` and
`ipv6`) are parsed into the 12-byte block record: for a `*` country the type is copied into the
4-byte code with `strcpy_s(code, 4, type)`. `"asn"` fits, `"ipv4"` and `"ipv6"` need 5 bytes.

## Effect

`strcpy_s` empties the code and calls the CRT's invalid parameter handler. With the handler of
`BSInstallSETranslator` the parser throws out of the slave's 0x6319 job (the file buffer stays
allocated and no 0xA319 answer is sent); with the CRT's default handler the process ends. If the
handler returned, the ipv4 and ipv6 types would not be recorded and the next pass over the
summary types throws `std::out_of_range`. Either way no IPv4 record of a real RIR file is ever
stored, so the IP country table can only hold what GM-021 puts into it.

## Fix

Give the code room for the type (or compare the type token directly instead of copying it).
