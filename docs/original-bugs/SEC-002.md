# SEC-002: random prime search can divide by zero or return 1

- Original: `KeyExchange_IsPrime` 0x49a380, `KeyExchange_RandomPrime` 0x49a2f0 (GatewayServer)
- Rewrite: `KeyExchange_IsPrime`, `KeyExchange_RandomPrime` in
  `JMX_Library/BSNet/security/KeyExchange.cpp`
- Severity: crash (rare)

## What the original does

`KeyExchange_RandomPrime` starts at `Data1 & 0x7FFFFFFF` of a new GUID, makes it odd and steps
by 2 until `KeyExchange_IsPrime` accepts it. `KeyExchange_IsPrime(n)` draws five witnesses as
`rand() % (n - 3) + 2` and checks `w^(n-1) mod n == 1`. Small start values are not handled:

- start value 2 or 3 gives `n = 3`, and `rand() % 0` raises an integer divide-by-zero;
- start value 0 or 1 gives `n = 1`; the exponent `n - 1` is 0, the power returns 1 and 1 is
  accepted as prime, which makes the generator or the modulus 1.

The test is also a plain Fermat test with unseeded `rand()`, so Carmichael numbers can pass.

## Effect

About one in 2^30 prime draws hits the divide-by-zero, which is an unhandled exception in the
thread that starts the handshake (two draws per key-exchange handshake). A modulus of 1 makes
every public value and the shared secret 0.

## Fix

Start the search at a minimum such as 5 and use a proper probabilistic primality test with a
seeded generator.
