# DL-001: an empty patch relay names its directory from uninitialised bytes

- Original: `CDownloadServerMainProcess::OnMsg_6305_impl_StartPatchRelay` (0x401820), DownloadServer
- Rewrite: `CDownloadServerMainProcess::OnMsg_6305` in
  `JMX_CommonServers/DownloadServer/DownloadServerMainProcess.cpp`
- Severity: low

## What the original does

0x6305 carries a WORD count and that many 550-byte patch file records. While reading them the
handler keeps the module ID (byte 10) and byte 9 of each record in two stack bytes; after the loop
it formats the receive directory `"%d_%d"` from them and starts fetching the files. The two bytes
are only written inside the loop. With a count of 0 they are never set, so the directory name is
made of whatever was on the stack.

## Effect

Nothing is fetched in that case anyway: the file transfer finds an empty list, asserts and returns
without a request. The module version data has already been replaced by the empty list, the
sender still gets 0xA305 {1} and the log says "start patch relay : 0".

## Fix

Return early (or answer a failure) when the list is empty, or initialise the two bytes.
