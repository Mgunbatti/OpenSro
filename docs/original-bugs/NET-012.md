# NET-012: keep-alive reconnects block session closes

- Original: `KeepAlive_TryConnect` 0x481a30 (GatewayServer)
- Rewrite: `CNetEngine::TryKeepAliveConnect` in `JMX_Library/BSNet/KeepAlive.cpp`
- Severity: minor

## What the original does

The maintainer's keep-alive job walks the keep-alive list with the engine lock at `+0x9C` held
and calls `ConnectSockAddr` (a blocking `connect`) for every entry without a session. The same
lock is taken by `CleanupDisconnectedSessions` and by `Session_CloseInternal` for every connected
session (`KeepAliveList_ClearSession`).

## Effect

While a keep-alive target is unreachable, each tick holds the lock for the duration of the failed
connects (about a second per target on Windows, up to the TCP timeout for silent hosts). Closing
any outgoing session, and therefore the I/O thread that closes it, waits that long.

## Fix

Copy the entries that need a connect, release the lock, connect, then store the results under
the lock.
