# SM-006: Reading past the end of a reference data row

- Original: `RefDataRow_ReadString` (0x4a1e30) and the inline column reads of every reference
  data reader (e.g. `RefTriggerCategory::Read` 0x499ff0), SR_ShardManager
- Rewrite: `CRefRow::operator>>` in `SilkroadOnline/Server/ServerCommon/ReferenceData.h` / `.cpp`
- Severity: crash

## What the original does

The readers take the columns of a `_Ref` row one after the other from the stream buffer of its
record. A scalar column (BYTE / WORD / DWORD / float) that does not fit into the rest of the row
only triggers an assert; the value is then read from behind the row data and the read position
moves past the end. A string column that does not fit asserts and rethrows without an active
exception, which ends the process.

## Effect

A row with fewer or narrower columns than the reader expects (a table from another version, a
changed column type) gives garbage values for the scalar columns and then, at the next string
column, terminates the ShardManager during start-up.

## Fix

Check the remaining size once per row and reject the row (or the table) with a log line.
