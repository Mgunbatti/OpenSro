# GM-005: the patch record progress is one message behind

- Original: `COverlapJob_RecordPatchData::vf06` (0x425330), GlobalManager
- Rewrite: `COverlapJob_RecordPatchData::Execute` in
  `JMX_CommonServers/GlobalManager/ServiceManagerJobs.cpp`
- Severity: low

## What the original does

While an uploaded patch is written to `_ModuleVersionFile`, the job computes the percentage of files
done after every file and sends 0x3101 {2, 2, percent} to the SMC when it moved by more than one
point. The byte it writes is the percentage of the previous message; the new value is stored only
after the message was sent.

## Effect

The SMC sees 0, then the earlier values; the last message of a patch reports the value before the
end (66 for three files), never 100. 0x3102 still reports the result.

## Fix

Store the new percentage before writing it.
