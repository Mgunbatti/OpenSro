# DB-002: Execute frees an uninitialised statement handle

- Original: `CDBSessionMgr::ExecuteQuery` (0x41cb80), GatewayServer
- Rewrite: `CDBQuery::Execute` in `JMX_Library/BSLib/DB/DBQuery.cpp`
- Severity: minor (environment dependent)

## What the original does

The query runs inside `__try` / `__finally`; the termination handler calls
`SQLFreeStmt(hStmt, SQL_CLOSE)` and `SQLFreeHandle(SQL_HANDLE_STMT, hStmt)`. The statement handle
is a local that is only written by `SQLAllocHandle`. When the pool has no connection with index
`m_nSession` (NULL pool, index out of range) the function logs "cannot occupy db session" and
returns -1 before the handle was ever written, and the handler passes whatever was on the
stack to ODBC.

## Effect

The driver manager receives a random value as a statement handle. The Windows driver
manager validates handles and returns `SQL_INVALID_HANDLE`, so normally nothing happens; if the
value happens to be a live statement handle (left by an earlier call at the same stack depth),
that statement is closed and freed under its owner.

## Fix

Initialise the handle to `SQL_NULL_HSTMT` and only free it when it was allocated.
