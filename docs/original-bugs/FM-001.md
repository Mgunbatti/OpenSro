# FM-001: a refused second cord session is still treated as established

- Original: `ServerCord_OnEstablished` (0x4134f0) and `CServerProcessMain::OnMsg_2001` (0x4029c0),
  FarmManager (2007 framework)
- Rewrite: `ServerCord_OnEstablished` in `JMX_ServerFramework/ServerFramework/ServerBody.cpp` and
  `CServerProcessMain::OnMsg_2001` in `ServerProcessMain.cpp` (`JMX_FRAMEWORK_2007`)
- Severity: low

## What the original does

When a peer introduces itself (0x2001) on a new session for a cord that already has a session,
the 2007 framework logs "server cord already established : created session overlapped : %d,
%s(%d)" and disconnects the new session, but returns the cord all the same. `OnMsg_2001` then
continues as for a newly established cord: it answers the introduction on the closed session,
sets the cord status to 2, calls `OnCordEstablished` (FarmManager sends 0x6306 again on the cord's
old session and drops its patch file data) and sends the 0x2005 / 0x6005 massive messages to the
closed session.

## Effect

Every duplicate connection of a peer makes FarmManager drop and re-request its patch file data
from the GlobalManager and broadcast a cord status that did not change. The messages for the
refused session are lost.

## Fix

Return NULL after disconnecting the new session (the 2008 framework instead replaces the old
session).
