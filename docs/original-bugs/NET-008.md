# NET-008: a file transfer offset only moves the byte counter

- Original: `CSession::OpenSendFile` 0x4929d0 (GatewayServer)
- Rewrite: `CSession::OpenTransferFile` in `JMX_Library/BSNet/FileTransfer.cpp`
- Severity: wrong

## What the original does

With a positive offset below the file size the function calls `IFile::Seek(context)` and sets
the transferred byte count to the offset. `IFile::Seek` only checks that the context has the file
open; it does not take a position and moves nothing.

## Effect

Resumed transfers (`SendFile` / `BeginSessionFileTransfer` with an offset) start reading or
writing at position 0 while the counter claims `offset` bytes are done. The sender stops
`offset` bytes early and the receiver reports completion `offset` bytes early; the result is a
truncated or misplaced file.

## Fix

Set the context's position to the offset (an `IFile::Seek(context, position)`).
