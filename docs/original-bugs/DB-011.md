# DB-011: Trailing blanks are trimmed past the end of a truncated value

- Original: `CDBSessionMgr::ExecuteQuery` (0x41cb80), GatewayServer
- Rewrite: `CDBQuery::Execute` in `JMX_Library/BSLib/DB/DBQuery.cpp`
- Severity: minor

## What the original does

Character columns (`SQL_CHAR`, `SQL_VARCHAR`, `SQL_LONGVARCHAR`) are read with `SQLGetData`
into the rest of the row buffer and then trimmed with `StrTrimRightSpaces(p, indicator)`, which
starts at `p[indicator - 1]`. When the value does not fit, the indicator is the full length of
the value (or `SQL_NO_TOTAL`), not the number of bytes written.

## Effect

The trim reads and zeroes blanks beyond the bytes that were written: past the end of the row
and, for the last row, past the end of the caller's buffer. With `SQL_NO_TOTAL` (-4) the pointer
starts before the value.

## Fix

Trim at most the number of bytes written (`min(indicator, buffer length)`).
