# DL-002: USER_LIMIT counts every engine session

- Original: `CDownloadServerMainProcess::OnSessionCreated_EnforceUserLimit` (0x4014b0),
  DownloadServer
- Rewrite: `CDownloadServerMainProcess::OnSessionCreated` in
  `JMX_CommonServers/DownloadServer/DownloadServerMainProcess.cpp`
- Severity: low

## What the original does

With Server.cfg `USER_LIMIT` set, the 0x1001 handler of an accepted session asks the engine for
its session statistics and closes the session when the number of sessions in use is greater than
the limit. That number includes the session just accepted and every server connection of the
module (the certification server, the GlobalManager and the other cords), not only clients. The
0x1001 data is only peeked (the read position is restored), and a refused session skips the base
handler that would read it.

## Effect

The real client limit is `USER_LIMIT` minus the server connections, so it changes when cords
come and go. Every refused client also produces the log line
"msg is not completely used" for its unread 0x1001.

## Fix

Count the accepted client sessions separately and compare them with the limit, and read the
0x1001 data on the refusing path too.
