# GM-017: a billing heartbeat timeout neither closes the session nor reconnects

- Original: `ActivateNetwork`-named 0x4521b0 (CStandardBillingMgr::OnTimer) and `sub_4519B0`
  (CloseSession), GlobalManager
- Rewrite: `CStandardBillingMgr::OnTimer` in
  `JMX_CommonServers/GlobalManager/Billing/StandardBillingMgr.cpp`
- Severity: medium

## What the original does

When the heartbeat answer timer fires ("Heartbeat Timeout!") the manager stops the heartbeat
timers, calls CloseSession and arms the reconnect timer. CloseSession only disconnects while the
manager is stopping (state 3), so the session stays open and the state stays "activated"; the
reconnect timer only connects in the idle state.

## Effect

After a lost heartbeat answer no heartbeat is sent any more and no reconnect happens while the
dead session is not closed by the network library. The manager still reports itself ready and
keeps sending logins into the stale session.

## Fix

Disconnect the session on a heartbeat timeout (or let the reconnect timer handle the activated
state).
