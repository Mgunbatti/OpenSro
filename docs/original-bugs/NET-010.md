# NET-010: DumpMsgPool walks the in-use set without the pool lock

- Original: `CNetEngine_MsgPool_DumpEntries` 0x482c60 (GatewayServer)
- Rewrite: `CMsgPool::DumpEntries` in `JMX_Library/BSNet/MsgPool.cpp`
- Severity: crash

## What the original does

`CNetEngine::DumpMsgPool` (server.cfg `DumpMsgPool`) iterates the pool's `std::set` of handed-out
messages and reads each message's opcode, with neither the pool lock nor the engine's message
lock held.

## Effect

Every network and worker thread allocates and frees messages at the same time, which inserts
into and erases from the set. The iteration can follow freed tree nodes (an access violation, or
an out_of_range from the checked iterators) or count garbage.

## Fix

Hold the pool lock (`m_cs`) while walking the set.
