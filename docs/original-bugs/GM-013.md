# GM-013: the automated punishment query is formatted twice

- Original: `COverlapJob_AutomatedPunishmentJob::vf06` (0x427700), GlobalManager
- Rewrite: `COverlapJob_AutomatedPunishmentJob::Execute` in
  `JMX_CommonServers/GlobalManager/ServiceManagerJobs.cpp`
- Severity: medium

## What the original does

The job formats `EXEC _RegisterAutomatedPunishment '%s',%d,'%s','%s','%s',%d` with sprintf_s into a
buffer and passes that buffer as the format of `DBQuery_FormatAndExecute`. The account name and the
three texts of the validation history are inserted without escaping.

## Effect

A `%` in the account name or the texts is interpreted a second time (reading arguments that were
never passed, possibly crashing the overlap thread); a quote breaks the statement or injects SQL.

## Fix

Pass the text with "%s" (or execute it directly) and escape the strings.
