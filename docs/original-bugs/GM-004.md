# GM-004: the 0x8023 answers are never released

- Original: `CServiceManagerProcess` 0x4023 handler (sub_44A9D0) and 0x8023 handler (sub_44AB40),
  GlobalManager
- Rewrite: `CServiceManagerProcess::OnMsg_4023` / `OnMsg_8023` in
  `JMX_CommonServers/GlobalManager/ServiceManagerAccount.cpp`
- Severity: low

## What the original does

Both handlers allocate a `CMsg` from the engine for the 0x8023 answer to the SMC (`{0}` when the
massive relay of 0x4023 fails, `{1}` when the target body answered), send it with
`IBSNet::SendMsg` and do not call `IBSNet::ReleaseMsg` afterwards, unlike every other handler.
`SendMsg` takes its own reference, so the handler's reference is never dropped. The 0x8023 handler
also calls the release of its context without checking it: without context it calls through a
NULL object.

## Effect

Each 0x4023 request leaks one message of the engine's pool (about 4 KB). The pool grows; the
memory comes back only at exit.

## Fix

Release the message after sending it, and check the context in the 0x8023 handler.
