# AS-006: a forwarded client packet is released twice

- Original: `CAgentMainProcess::OnUnhandledMsg` (vf09, 0x401d00) with `CAgentMainProcess::Run` (vf03, 0x404310), AgentServer
- Rewrite: `CAgentMainProcess::OnUnhandledMsg` in `JMX_CommonServers/AgentServer/AgentMainProcess.cpp`
- Severity: medium

## What the original does

A packet of a logged-in client gets the user's JID appended and goes to the game server with
`ServerBody_SendMsg`, which sends and releases the message. The message is the one the message loop
popped from the task queue, and the loop releases it again after the handler returns. The framework's
own relay of a received message (`OnMsg_6008`) takes an extra reference first; this handler does
not.

## Effect

Each forwarded packet loses one reference too many: the message can go back to the pool while the
socket still sends it, and the second release can hit the message's next user. With the rewrite's
engine on the test's loopback connections the receiving side drops the cord after such a forward.

## Fix

`InterlockedIncrement(&pMsg->m_lRefCount)` before `ServerBody_SendMsg`, as `OnMsg_6008` does.
