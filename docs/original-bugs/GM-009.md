# GM-009: the silk change message is released twice when the relay fails

- Original: `COverlapJob_RefreshCommercialUser_Cash::vf07` (0x4132f0), GlobalManager
- Rewrite: `COverlapJob_RefreshCommercialUser_Cash::OnComplete` in
  `JMX_CommonServers/GlobalManager/GlobalManagerJobs.cpp`
- Severity: medium

## What the original does

For every logged-in user with a silk change the job allocates 0x6A00 and relays it to the shard
manager with `RelayMsgToBody_6008`. That function releases the message in every case (also when
there is no route or the send fails). When it returns false the job releases the message a second
time.

## Effect

A shard manager without route (or a failed send) drops an extra reference of a pooled message: the
message returns to the pool while it may already be reused, which can corrupt later messages.

## Fix

Do not release the message after `RelayMsgToBody_6008`.
