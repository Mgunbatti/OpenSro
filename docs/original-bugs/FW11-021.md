# FW11-021: CDatabase::DestroySession dereferences a missing session registry

- Original: `CDatabase::DestroySession` (0x4c8a40), GlobalManager (January 2011 library)
- Rewrite: `CDatabase::DestroySession` in `JMX_Library/BSLib/DB/Database.cpp`
  (`JMX_FRAMEWORK_2011_01`)
- Severity: low (GlobalManager destroys its session before `DestroyAllSessions`)

## What the original does

The January 2011 library keeps the registry of open session pools on the heap: `InitEnvironment`
creates the `std::set`, `DestroyAllSessions` deletes it and sets the pointer to NULL.
`CreateSession` only reaches the registry after the environment check, and `DestroyAllSessions`
returns at once without a registry, but `DestroySession` searches the set through the pointer
without checking it.

## Effect

`DestroySession` called before `InitEnvironment` or after `DestroyAllSessions` reads through a
NULL pointer and the process faults (the 2008 library, with a static set, simply finds nothing).

## Fix

Return when the registry pointer is NULL.
