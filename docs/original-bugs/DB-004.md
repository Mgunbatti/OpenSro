# DB-004: SQLSTATE and message are compared uninitialised when there is no diagnostic record

- Original: `CDatabase::HandleSQLError` (0x47b200), GatewayServer
- Rewrite: `CDatabase::HandleSQLError` in `JMX_Library/BSLib/DB/Database.cpp`
- Severity: minor

## What the original does

After the diagnostic loop the function compares the SQLSTATE buffer with "08S01" (and then
logs "Database Connection was lost!!! Server should be shutted down !!!") and returns the
comparison of the message buffer with "Connection is busy". Both are stack arrays that only
`SQLGetDiagRec` fills. When its first call returns `SQL_NO_DATA`, `SQL_ERROR` or
`SQL_INVALID_HANDLE` (no record, invalid handle) they were never written.

## Effect

The comparisons read leftover stack data: in rare cases the "connection lost" line is logged
for an unrelated error, and the return value is meaningless (the callers ignore it).

## Fix

Clear both buffers before the loop.
