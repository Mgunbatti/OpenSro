# GM-002: the SMC login row is not initialised

- Original: `CServiceManagerProcess` 0x7001 handler (sub_443540), GlobalManager
- Rewrite: `CServiceManagerProcess::OnMsg_7001` in `JMX_CommonServers/GlobalManager/ServiceManagerAccount.cpp`
- Severity: medium

## What the original does

The login runs `_CertifyUser` (or `_CertifyUser_For_SMC` in divisions 20 and 29) into an 8-byte
row on the stack: the account's nID and a security byte. The row is not cleared before the query.
`CDBQuery` leaves the row untouched when the procedure returns no row (result 1, which is not an
error), and the handler then decides on whatever the stack held: a non-zero "nID" passes, and the
stale byte is used as the group of the `SMC_Login` privilege check and becomes the user's security
byte.

## Effect

A login that the procedure does not answer with a row may be accepted with a garbage account ID
and security byte instead of being refused with error 2. It depends on the previous contents of
the stack (the main process' task thread), so it is not reproducible on purpose but cannot be
ruled out.

## Fix

Clear the row before the query (or treat result 1 as "refused").
