# DB-009: GetData fetch leaks the record on a failed SQLGetData

- Original: `CDBTable_FetchRowsViaGetData` (0x477870), GatewayServer
- Rewrite: `CDBTable::FetchWithGetData` in `JMX_Library/BSLib/DB/Database.cpp`
- Severity: minor

## What the original does

For every row a record is created with `CreateBoundHelper`, then each column is read with
`SQLGetData`. When `SQLGetData` fails the function jumps to its error handling; the record is
neither appended to the result list nor returned to the allocator.

## Effect

One record object is leaked per failed fetch. In addition any failure of the `SQLFetch` that
moves to the next row ends the loop as success. The Gateway does not call the function.

## Fix

Free the record before leaving and report `SQLFetch` errors.
