# GW-001: unknown shard ID in 0x6105 writes through a NULL pointer

- Original: `CGatewayMainProcess::OnMsg_6105_UpdateShardField557` (0x406400), GatewayServer
- Rewrite: `CGatewayMainProcess::OnMsg_6105` in `JMX_CommonServers/GatewayServer/GatewayMainProcess.cpp`
- Severity: medium

## What the original does

0x6105 carries a count and (WORD shard ID, WORD user count) pairs. For each pair the handler
looks the shard up with `Map53B744_Find` (the certified shard map), which returns NULL for an
unknown ID, and stores the user count at offset 557 of the result without checking it.

## Effect

A pair with a shard ID that is not certified writes to address 557: an access violation. The
process loop of the main process catches it and closes the session that sent the packet; pairs
after the bad one are lost. The opcode is not restricted to server sessions, so any client that
completed the handshake can trigger the fault (and the crash dump / log handling of it).

## Fix

Skip pairs whose shard is unknown (and accept 0x6105 only from server cords).
