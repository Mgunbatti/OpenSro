# GM-024: the IP table files are parsed past the end of their buffers

- Original: `sub_461EE0` (0x461ee0, IP country table, file reader) and the parser around it
  (`sub_4618A0`, `sub_462010`, `sub_462270`), GlobalManager
- Rewrite: `CIPCountryTable::ReadWholeFile`, `NextToken`, `NextLine`, `ParseCountryLine` in
  `JMX_CommonServers/GlobalManager/IPCountryTable.cpp`
- Severity: medium

## What the original does

A country code or RIR file is read into a buffer of exactly its size, without a terminating 0.
The parser takes the lines with `lstrlenA` and a search for "\r\n" starting at the cursor. The
line count of the country code file (first line) is trusted.

## Effect

Every search runs `lstrlenA` from the cursor to the first zero byte, which lies after the
buffer in heap memory; the token search does so once per character, so every character of a line
costs a scan of the rest of the file (for a delegation file of some megabytes that adds up to
minutes). Past the last
line the parser reads heap data: a stray "\r\n" there yields a garbage line, a page end can
fault. When the count of the country code file is larger than its lines (or the last line has
no "\r\n"), `NextLine` returns NULL and the line parser calls `strlen(NULL)`, which faults on the
slave thread.

## Fix

Allocate one byte more and terminate the data; stop at the end of the data instead of trusting
the count.
