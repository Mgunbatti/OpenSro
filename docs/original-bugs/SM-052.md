# SM-052: A fortress area without its region is reported as an unknown fortress

- Original: `RefData_CheckRegionAssocServerSetting` (0x4e6c20), SR_ShardManager
- Rewrite: `RefData_CheckRegionAssocServerSetting` in
  `SilkroadOnline/Server/ServerCommon/RefDataTeleport.cpp`
- Severity: minor

## What the original does

After `_RefRegionBindAssocServer` is built, the check copies the rows into a map (AreaName to
AssocServer) and walks eight hard-coded pairs (FORT_JA_AREA / CHINA ... FORT_SK_AREA / Ca). A
pair is compared, and the fortress removed from the map, only when both names are in the map.
Afterwards any name left in the map that starts with "FORT" is treated as a fortress without a
hard-coded entry.

## Effect

When a known fortress area (for example FORT_SK_AREA) has a row but its region (Ca) has none,
the server stops with "There's no hardcoded entry for Sirge Fortress!! Please update source code
for entry!!", which points at the code instead of the missing region row.

## Fix

Report the missing region row by name, or compare only the pairs whose fortress is present and
say which partner is missing.
