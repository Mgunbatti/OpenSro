# SM-002: A blank CHAR column is stored as one blank instead of an empty string

- Original: `DBRecord_TrimTrailingSpaces` (0x402c40), called by `CDBRecord::SetField` (0x402bd0)
  and `CDBRecStream::SetField` (0x61a430), SR_ShardManager
- Rewrite: `DBRecord_TrimTrailingSpaces` in `JMX_Library/BSLib/DB/Database.cpp`
- Severity: minor

## What the original does

The fetched value of a string column is cut at `nSize - 1`, then the trailing blanks are
replaced by zeros from `nSize - 2` down to, but not including, the first character
(`for (p = &v[nSize - 2]; p != v; --p)`).

## Effect

A CHAR column that holds only blanks (an "empty" fixed-length value) keeps its first blank:
the record gets `" "` and a stream record writes length 1 instead of taking the empty-string
path. Code comparing such a column with `""` sees a non-empty value.

## Fix

Run the loop down to and including the first character.
