# FW11-023: NewSchedule clears structures that hold std::string with memset

- Original: `ISchedule::ISchedule` (0x6d7170), `CScheduleGroup::CollectActivePeriods` / `GetPrevPeriods` / `GetNextPeriods` (0x6c7a10, 0x6c7c30, 0x6c7e80), `CScheduleManager::RebuildEventList` / `ProcessDueEvents` / `AddSchedule` / `PushEvent` (0x6bf740, 0x6bfca0, 0x6c0090, 0x6c07c0), `sScheduleEvent::ToScheduleInfo` (0x6c0310), SR_ShardManager
- Rewrite: `ZeroScheduleStruct` calls in `JMX_Library/BSLib/NewSchedule/Schedule.cpp` and `ScheduleManager.cpp`
- Severity: low (16 bytes per short schedule name and event)

## What the original does

Periods (`sSchedulePeriod`), events (`sScheduleEvent`) and job infos (`sScheduleInfo`) are constructed and then zeroed as a whole. The zeroed `std::string` reports a capacity of 0 although it still uses its internal buffer.

## Effect

The next assignment of a name shorter than 16 characters allocates a 16-byte block, stores its pointer in the internal buffer, keeps the capacity at 15 and overwrites the pointer with the characters: the block is lost. This happens for every computed period and every queued event, so a long-running ShardManager leaks a little memory with every schedule event. Longer names are not affected.

## Fix

Clear only the scalar members (or value-initialise the structures).
