# NET-013: a second disconnect overwrites the close reason of an accepted socket

- Original: `Socket_DisconnectReuse` 0x46e2e0 (GatewayServer), reached from
  `SessionTable_Close` 0x494750
- Rewrite: `CSockStream::DisconnectReuse` in `JMX_Library/BSNet/SockStream.cpp`
- Severity: minor

## What the original does

`DisconnectReuse` computes "already closing" (close state set, result 2) or "no session"
(result 3) but acts on it only for reason 2. For any other reason it stores the new reason in
the close state and posts another `TransmitFile(TF_DISCONNECT | TF_REUSE_SOCKET)` on the same
socket. `SessionTable_Close` calls it for every close of an accepted session with a reason other
than 6.

## Effect

When an accepted session is disconnected (for example by the server with a reason) and the peer
then drops the connection, the failed receive closes the session again with reason 3: the close
state, and so the parameter of the application's close event (0x1002), becomes 3 instead of the
original reason, depending on timing, and a second disconnect is posted on a socket that already
has one pending.

## Fix

Return 2 without touching the close state when a disconnect is already in progress, whatever the
reason.
