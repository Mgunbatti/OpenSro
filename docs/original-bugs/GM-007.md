# GM-007: the punishment jobs read results that were never set

- Original: `COverlapJob_QueryPunishment::vf06` (0x4269a0), `COverlapJob_PunishmentJob::vf06`
  (0x426f10), `COverlapJob_AutomatedPunishmentJob::vf06` (0x427700), GlobalManager
- Rewrite: `Execute` of the three classes in
  `JMX_CommonServers/GlobalManager/ServiceManagerJobs.cpp`
- Severity: medium

## What the original does

The JID of `exec _GetUserJID` and the result codes of `_RegisterPunishment`, `_UpdatePunishment` and
`_RegisterAutomatedPunishment` are read into a DWORD on the stack that is not initialised.
`CDBQuery` leaves the buffer untouched when the procedure returns no row (result 1, which is not an
error), and the job then decides on the stale value: a JID other than -1 is used for the following
queries, a non-negative result counts as success.

## Effect

A procedure that answers without a row (for example after an error inside it) leads to a query of a
random JID, or to a success answer (and an entry in the punishment manager) for a punishment that
was not stored, depending on the overlap thread's stack.

## Fix

Initialise the values (JID -1, result -1) or treat result 1 as a failure.
