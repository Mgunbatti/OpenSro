# MM-003: a module without window is always killed after the timeout

- Original: `ServerProcess_CloseOrTerminate` (0x401620), MachineManager
- Rewrite: `MachineManager_CloseOrTerminateProcess` in
  `JMX_CommonServers/MachineManager/MachineManagerMainProcess.cpp`
- Severity: low

## What the original does

To stop a module the function looks for its window (class and title = module name). When there
is none it finds the process by exe name, but still calls `PostMessageA(hWnd, WM_CLOSE, 0, 0)`
with the NULL window handle. With NULL `PostMessageA` posts a thread message to the calling
thread, i.e. MachineManager's own main process thread, which has no message loop.

## Effect

A module that runs without its window (for example a console or service run) never gets a close
request. MachineManager waits the whole ShutdownProcessTimeout (15 s by default) and then kills it
with `TerminateProcess`, logging "terminate server process abnormaly". A WM_CLOSE thread message
is left in MachineManager's queue each time.

## Fix

Only post WM_CLOSE when a window was found; otherwise ask the process to end in another way (or
terminate it right away and say so).
