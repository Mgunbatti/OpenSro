# GM-014: active punishments of the types 0 to 2 are written before the answer buffer

- Original: `sub_4595D0` (0x4595d0, CPunishmentManager, 0x6318), GlobalManager
- Rewrite: `CPunishmentManager::GetActive` in
  `JMX_CommonServers/GlobalManager/PunishmentManager.cpp`
- Severity: medium

## What the original does

The answer to 0x6318 has one 17-byte entry (BYTE active, SYSTEMTIME end) per punishment type. The
entry of a punishment is written at `buffer + 17 * (type - 3)`; only types above 4 are caught (by
an assertion that does not stop the write). `PunishmentManager_Add` refuses the types 1 and 2, but
the punishments loaded at start (`_QueryActivePunishmet`) are taken with any type.

## Effect

An active punishment of type 0, 1 or 2 from the database writes 17 bytes 51, 34 or 17 bytes before
the caller's buffer, on the main process' stack.

## Fix

Ignore (or log) types outside 3..4 instead of indexing with them.
