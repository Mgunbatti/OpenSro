# SM-240: _Friend_Remove error codes are never recognised

- Original: `CMessenger::RemoveFriend` (0x446930), SR_ShardManager
- Rewrite: `CMessenger::RemoveFriend` in `SilkroadOnline/Server/ShardManager/Messenger.cpp`
- Severity: cosmetic

## What the original does

The return value of `{?=CALL _Friend_Remove (%d,%d)}` is fetched with
`CDatabase::ExecDirectWithReturnValue` and flags 3 (int and bigint; the int wins), so only the
low four bytes of the zeroed `__int64` buffer are written. A non-positive result is then checked
with a 64-bit switch for -1001, -1000, -2 and -1, which assert. The high half of the buffer is
always 0, so none of these cases matches.

## Effect

Every failure of the procedure returns 2 silently; the asserts meant for the known error codes
never fire.

## Fix

Read the result as an int (or request only the bigint return value).
