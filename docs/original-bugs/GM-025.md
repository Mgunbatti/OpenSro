# GM-025: a failed silk history poll is repeated on every pass of the slave's loop

- Original: `sub_45C8C0` (0x45c8c0, CGlobalManagerSlave, silk history poll), GlobalManager
- Rewrite: `CGlobalManagerSlave::PollSilkHistory` in
  `JMX_CommonServers/GlobalManager/GlobalManagerSlave.cpp`
- Severity: medium

## What the original does

The poll is due when five minutes have passed since the time stored at +0x400D0. That time is
only stored right before the 0x231B message is relayed, after both queries succeeded and only
when the main process is known. A failed query logs "You cannot support Silk History Function
for User... (ErrCode:0xA8)" or "(ErrCode:0x71)" and returns.

## Effect

The slave's loop runs the poll after every pass (at most a millisecond apart while the queue is
empty), so a silk DB that fails the query is queried and the error logged about a thousand times
a second until it answers. Without the main process the queries succeed but the message is
neither sent nor released, also on every pass.

## Fix

Store the poll time before the queries (or after any attempt).
