# FW11-026: CSchedule_Once_Date mixes up time fields

- Original: `NewSchedule::CSchedule_Once_Date::GetCurrentPeriod` (0x6dc490) and `AdvanceToNextPeriod` (0x6dc610), SR_ShardManager
- Rewrite: the same functions in `JMX_Library/BSLib/NewSchedule/Schedule.cpp`
- Severity: low (seconds only)

## What the original does

`GetCurrentPeriod` builds the end of the one-time period from the end date with the second of the start. `AdvanceToNextPeriod` builds "end + 30 minutes" with the end minute as second.

## Effect

The end of a one-time schedule is off by up to 59 seconds unless both times have the same second; the time after the end is off by up to 59 seconds as well.

## Fix

Use `stEnd.wSecond` in both places.
