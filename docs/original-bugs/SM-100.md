# SM-100: A second climate row with the same ID leaks its CClimate

- Original: `CClimateManager::AddClimate` (0x657160), SR_ShardManager
- Rewrite: `CClimateManager::AddClimate` in `SilkroadOnline/Server/ShardManager/Climate.cpp`
- Severity: minor (with broken data only)

## What the original does

AddClimate allocates and initialises a CClimate for the _RefClimate row before it looks the
row ID up in its map. When the ID is already there it asserts and returns without deleting the
new object. Init has already clamped Division and Duration in the row.

## Effect

Duplicate climate IDs leak 0x38 bytes each at start-up; the first row of the ID stays in use.
The rewrite does the same.

## Fix

Look the ID up first, or delete the new CClimate before returning.
